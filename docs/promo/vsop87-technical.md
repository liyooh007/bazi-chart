# 我如何用 Python 把 24 节气算到和 JPL DE441 只差 1 分钟

> 技术向文章初稿（掘金 / 知乎 / V2EX / 少数派皆可发）。全文只谈天文历法与工程，不涉及命理预测。
> 配图建议：①太阳视黄经→节气的迭代示意；②240 个节气点与 DE441 的误差柱状图（可跑脚本生成）。

## 一、问题：为什么不直接查一张节气表

做中国传统历法相关的程序，最省事的办法是内置一张节气时刻表——网上能找到逐年数据，查表 O(1)。但查表有三个硬伤：

1. **年份受限**：表覆盖到哪年就算到哪年，历史日期和未来日期都没有；
2. **无法做真太阳时**：真太阳时需要"均时差"（equation of time），它是连续函数，表里没有；
3. **无法验证**：你不知道表本身从哪来、精度如何，错了也无从查起。

所以在开源项目 bazi-chart 里，我选择从天体力学出发实时计算二十四节气。目标是：**1900–2050 年间，和 NASA/JPL 的 DE441 数值星历对表，误差不超过 1 分钟**。最终 240 个节气点实测达到了这个目标。这篇文章讲清楚中间每一步，以及踩过的坑。

代码：https://github.com/liyooh007/bazi-chart （核心在 `bazi/astro.py`，约 300 行，纯标准库）

## 二、二十四节气的天文学定义

节气不是"某几天"，而是一个**精确时刻**：太阳的**视黄经**（apparent ecliptic longitude）到达 15° 整数倍的瞬间。

- 春分：视黄经 = 0°
- 清明：15°，谷雨：30°……
- 每个节气间隔 15°，一圈 360° 共 24 个。

注意是"**视**黄经"——从地球看过去、经过光行差和章动修正后的位置，不是 J2000 平春分点下的几何黄经。这个区别是精度的关键，后面细说。

所以问题转化为两步：

1. 给定时刻，高精度求太阳视黄经 λ(t)；
2. 解超越方程 λ(t) = 15°·k，求时刻 t。

## 三、时间尺度：UT、TT、ΔT，最容易被忽略的一步

新手（包括最初的我）最容易栽在时间上。天文公式里的自变量是**力学时 TT**（Terrestrial Time，近似旧称 ET），而我们日常用的是**世界时 UT/UTC**。两者之差是 **ΔT = TT − UT**，它不固定，由地球自转的长期变慢和潮汐决定：

- 1900 年 ΔT ≈ −3 秒；
- 2000 年 ≈ 64 秒；
- 2026 年 ≈ 70 秒；
- 越往古代/未来，差得越多，古代能差到几小时。

节气表是给老百姓用的，最终要落到 UT（再 +8 得北京时间）。如果你拿 UTC 直接塞进 VSOP 公式，**光 ΔT 就带来约 1 分钟级误差**，更别说古代。

项目里采用 Espenak & Meeus（NASA/GSFC 五千年 ΔT 目录）的分段多项式：

    ...

所有计算统一在 TT 里做，最后一步才转回 UT。这是"≤1 分钟"的第一道保险。

## 四、太阳位置：VSOP87D 截断级数

求行星位置的金标准是 JPL 的 DE 系列数值星历（DE440/DE441），但那是几百 MB 的二进制插值文件，不适合塞进一个零依赖 CLI。

折中方案是 **VSOP87**（Bretagnon & Francouur, 1987）行星分析历——用上万项周期/多项式级数展开拟合行星运动。Meeus 的《Astronomical Algorithms》第 32 章附录 III 给出了一个**截断版**：只取对地球日心黄经贡献最大的 L0–L5 共 129 项，在 1950–2050 区间误差约 1 角秒。换算成时间，太阳在黄道上约每天走 1°（3600 角秒/天），故 1 角秒对应约 **24 秒**，对"节气精确到分钟"的目标绰绰有余。

实现上分三层：

```python
def _series(terms, tau):
    # 每项是 (A, B, C): L = Σ A·cos(B·τ + C)，tau 为 J2000 起算的儒略千年数(TT)
    return sum(A * cos(B*tau + C) for A,B,C in terms)

def earth_heliocentric_longitude(tau):
    L = (_series(L0,tau) + _series(L1,tau)*tau + ... )
    # 化到 0..2π
```

129 项纯 `math.cos` 求和，单次几毫秒，树莓派上也毫无压力——这是选截断级数而非加载星历文件的原因。

## 五、从"几何黄经"到"视黄经"：差之毫厘的两次修正

VSOP 给的是地球在**岁差框架**下的日心几何黄经。换算成观测到的太阳**视**黄经，还要两步修正（这也是很多简化实现漏掉、导致几十角秒系统偏差的地方）：

1. **章动 Δψ**（nutation in longitude）：自转轴的短周期摆动。取 IAU1980 理论的几个主项（日月项 + 月亮主项）：
   ```python
   def sun_apparent_longitude(jd_tt):
       lon = ...几何黄经...
       lon += nutation_in_longitude(t)/3600 * RAD   # 章动（角秒→弧度）
       lon -= 20.4898/3600 * RAD                     # 光行差（约 -20.49″）
   ```
2. **光行差**：光速有限，我们看到的太阳是约 8.3 分钟前的方向，黄经上近似恒定 −20.49″。

做完这两步，才是节气定义里真正要找的 λ。

这里有个实现细节：**黄经是 0–360 循环的**，比较残差必须先取最短角距（wrap 到 −180..180），否则跨春分点 0° 时迭代会朝错误方向狂奔。

## 七、均时差：真太阳时的另一根支柱

## 八、验证：用 DE441 当裁判

算法说再多，不如逐点对表。验证方法：

1. 用 JPL 提供的 DE441 星历（覆盖 13200 BC–17191 AD，是长期历法研究常用版本），通过天文库算出 1900–2050 每个节气的精确时刻，导出参考表（项目里是 `bazi/data/solar_terms_reference.py`）；
2. 用本引擎独立算出同一批 240 个节气；
3. 逐点比较北京时间差，取最大值。

实测结果：

- **1900–2050 的 240 个节气，最大偏差 ≤ 1 分钟；**
- 2100 年 24 个节气最大约 3 分钟，主要来自 ΔT 远期外推的模型分歧（ΔT 本身在远期就无法精确预测，这不是太阳位置算错了）。

配套的回归测试（`bazi verify`）还包括：73000+ 天农历公历往返零误差、日柱锚点、公开命盘四柱复现、400 个随机命盘的结构不变式。历法这种东西，**没有测试覆盖的"精确"都是口头精确**。

## 九、几个关键取舍

回头看，真正决定成败的不是 VSOP 公式本身（书里都有），而是这些工程取舍：

| 取舍点 | 选择 | 原因 |
|---|---|---|
| 星历来源 | VSOP87D 截断级数，不用 DE 二进制 | 零依赖、毫秒级、1950–2050 内 1″ 够用 |
| 时间尺度 | 全程 TT，仅最后转 UT | ΔT 不可忽略，是分钟级误差的主要来源之一 |
| 视位置 | 加章动 + 光行差 | 节气定义针对视黄经，漏了就是系统偏差 |
| 求解 | 割线法 + 黄经 wrap | 免导数、稳定，初值好给 |
| 验证 | DE441 逐点对表进 CI | 防止"改了别处悄悄破坏精度" |

## 十、可以继续深挖的方向

- 章动目前只取 IAU1980 主项，上完整 IAU2000/2006 章动模型可再压一点残差；
- 远期（>2100）精度瓶颈在 ΔT 而非行星理论，换更新的长期 ΔT 模型比升级 VSOP 更有效；
- 若要做到亚角秒/古代日食级别，才需要真正加载 DE 星历或用 Skyfield——那是另一个量级的工程。
